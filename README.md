# ArchiveCleaner

Высокопроизводительная утилита на C++, предназначенная для автоматического управления и очистки папок с архивами или данными путем сохранения только самых важных файлов за каждый месяц.

## Описание

В рабочих процессах архивирования часто требуется сохранять записи «начала месяца» и «конца месяца», в то время как промежуточные ежедневные бэкапы становятся избыточными со временем. **ArchiveCleaner** автоматизирует этот процесс. Программа сканирует указанные директории, группирует файлы по дате изменения (Год-Месяц) и оставляет ровно два файла для каждого месяца:
1. Самый ранний файл, найденный в этом месяце.
2. Самый поздний файл, найденный в этом месяце.

Все остальные файлы внутри этих месяцев удаляются автоматически.

## Ключевые особенности

* Высокая производительность: Написано на нативном C++ для минимальной нагрузки на систему, что делает его идеальным для выполнения в планировщике задач сервера (Task Scheduler).
* Безопасный режим отладки: Запуск с флагом `--debug` позволяет сформировать список файлов, которые были бы удалены, не совершая фактического удаления.
* Единый конфигурационный файл: Все настройки (папки, SMTP) в одном `config.ini`.
* HTML-отчет на email: После обработки отправляется отчет с таблицей удаленных файлов, временем выполнения и информацией о свободном месте на дисках.
* Подробное логирование: Каждый запуск создает уникальный лог-файл с временной меткой, содержащий отчет обо всех действиях.
* Надежная обработка ошибок: Программа пропускает файлы, которые заняты другими процессами или к которым нет доступа, записывая ошибку в лог и продолжая работу.

## Сборка проекта

### Через CMake (рекомендуется)
```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

### Вручную (MSVC Developer Command Prompt)
```
cl /nologo /EHsc /std:c++17 /DWIN32_LEAN_AND_MEAN /D_WIN32_WINNT=0x0601 /DNOMINMAX src\main.cpp src\Config.cpp src\Mailer.cpp ws2_32.lib /Fe:ArchiveCleaner.exe
```

Готовый бинарник появится в корне проекта.

## Конфигурация

Создайте файл `config.ini` рядом с исполняемым файлом (см. `config.ini.example`):

```ini
[General]
Folders = D:\BackUP_1\
          D:\BackUP_2\
          D:\BackUP_3\

[Mail]
Server = smtp.company.local
Port = 25
Auth = false
Username =
Password =
SenderName = Archive Cleaner Service
SenderEmail = archive@company.local
Recipients = admin@company.local
TemplatePath = report_template.html

[Log]
LogPath = Logs
MaxLogs = 30
```

Для обратной совместимости поддерживаются файлы `folders.txt` (список папок) и `email_config.txt` (настройки SMTP), но рекомендуется использовать единый `config.ini`.

## Использование

### Режим отладки (Тестовый запуск)
```
ArchiveCleaner.exe --debug
```
Будет создан файл `debug_delete_list.txt` со списком файлов, которые будут удалены.

### Рабочий режим (Удаление)
```
ArchiveCleaner.exe
```

## Email-отчет

После обработки утилита отправляет HTML-отчет на электронную почту через SMTP (напрямую по протоколу SMTP, без внешних зависимостей).

### Шаблон отчета `report_template.html`

HTML-шаблон письма с плейсхолдерами:
- `{{TIMESTAMP}}` - дата и время запуска
- `{{MODE}}` - режим (NORMAL / DEBUG)
- `{{TOTAL_DELETED}}` - количество удаленных файлов
- `{{TABLE_ROWS}}` - строки таблицы (папка, файл)
- `{{DURATION}}` - время выполнения
- `{{DRIVE_SPACE_ROWS}}` - информация о свободном месте на дисках

## Логирование

Лог-файлы сохраняются в папку `Logs\` (настраивается в `[Log]` → `LogPath`, относительно exe или абсолютный путь).

Каждый запуск создаёт новый файл `log_YYYYMMDD_HHMMSS.txt`. При старте программа автоматически удаляет самые старые логи, оставляя не более `MaxLogs` штук (по умолчанию 30). Отключить очистку: `MaxLogs = 0`.

В логах отображаются:
- Успешные операции удаления каждого файла.
- Уведомления о файлах, которые были оставлены (KEEP).
- Подробные сообщения об ошибках, если папка недоступна или файл заблокирован.
- Информация о свободном месте на дисках до и после обработки.
- Статус отправки email-отчета.

## Дисклеймер

Используйте с осторожностью! Данная программа выполняет безвозвратное удаление файлов. Всегда запускайте программу в режиме `--debug` перед первым использованием, чтобы убедиться, что логика корректно обрабатывает ваши данные.
